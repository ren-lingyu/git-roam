#+title: Phase B observation and validation acceptance evidence

* Source and method
Measured on 2026-11-12, x86_64-linux, Intel Core Ultra X7 358H, Git 2.56.0,
GHC 9.12.3. B6 baseline: =0376d2691cf1bf4abad00a476b41cb5bc4d9aa9a=.
B7 results use the uncommitted worktree's two bounded production optimizations;
no release version or protocol change. Before/after binaries use the identical
Haskell observation harness with respectively B6 and B7 production libraries.
The pinned package and its full default tests were built for both binaries.
Final integration acceptance, including the later native lazy-fetch regression,
is recorded in project memory; the benchmark binary does not claim those tests.

All tables report three samples per workload, median seconds. Fixture generation
is excluded from query time. OS caches are warm after generation; application
caches are fresh per query. Proxy launches and per-request logging are included.
The primary measurements below ran serially without a concurrent Nix build.
Earlier overlapping exploratory measurements are excluded from these tables.
Timing differences at small scales include startup/scheduling variation; no
absolute latency guarantee or statistical significance claim is made.

See [[file:README.org][harness instructions]] for exact reproduction, metric boundaries and options.

Peak RSS, cold-cache timings, Git 2.54 runtime compatibility, aarch64 execution
and large Deploy/Undeploy throughput were not measured. All four object/ref
combinations below were actually exercised; configured platforms are not tests.

* Independent Root fixtures
For N Nodes: N local refs, N remote-tracking refs, N unique tips/commits,
N+1 trees, one shared marker blob, three registered worktrees (two associated
with Nodes). No upstream config entries or diagnostics. All queries completed.
=tip-one= and =status-one= select one Node, with one associated worktree;
=status= selects both associated worktrees. Other queries do not scan files.
Processes are actual native Git launches; batch requests are distinct from
processes. Raw requests are N for commit and 2N+1 for Check, with one session.
Repo has zero ref enumerations; other queries have two. Ordered maps/sets and
native backend costs prevent a claim of strict linear wall-clock complexity.

* Architecture and Stage A handoff
Audit found no production Inspection presentation dependencies. Status is
independent of protocol validation; Check maps shared Validation evidence;
candidate validation does not enumerate live refs. Operations and Protection
retain strict acceptance/preflight/transition rules, and Output performs no
Git queries. Worktree/remote association already uses indexes, commit OIDs
are deduplicated, and history/object evidence is shared per invocation.

Full default regression retains the four-way native matrix, batch cancellation,
relative/non-UTF-8 worktrees, pack-refs maintenance and management safety.
New tests cover executable cross-command semantics, serialized diagnostic
contexts/evidence, partial-ref strictness, config failures and read-only state.
The native promisor regression records Git trace events to detect hidden lazy
fetches; it uses only a local unavailable remote, not a network server.

Deploy currently performs two exact-name occupancy probes per imported Node:
measured four probes for two imports, zero for an already-local re-deploy, in
all four functional combinations. Both checks remain. Stage A owns batch
Deploy/Undeploy planning, repeated global observations/replanning and complete
unsafe-removal diagnostics. It must preserve conditional non-dereferencing
creation, strict candidate validation, compensation and user-data protection.
No ten-thousand-worktree deployment claim follows from these observations.

Accepted bounds remain: Git can silently omit dangling symbolic refs; Check is
not a full ODB/rehash audit or transition verifier, does not collect every error,
and reports initial refs rather than atomic/current/per-Node-validated values.
Status partial results cannot certify management state; clean does not mean
safe removal; existing operation locks do not isolate arbitrary external writers.
Phase B completion does not release v0.3.0 or complete Stage A.
