* Development status
Version 0.1.0 is under development. Planned capabilities and their completion status are recorded in [[file:CHANGELOG.org][CHANGELOG.org]].

* Build and check
The Nix flake provides the executable and runs the Cabal test suites and formatting checks.

#+begin_src sh
  nix build .#default
  nix flake check .
  nix fmt
#+end_src

These commands use Git-tracked source files, including their current modifications. New files must be tracked or included in a clean source snapshot before they can be checked. Use a source snapshot without Git metadata when checking untracked implementation work.

* Available commands
#+begin_src sh
  nix run .#default -- --help
  nix run .#default -- --version
#+end_src

The installed executable is =git-roam=. When its directory is on =PATH=, Git exposes it as:

#+begin_src sh
  git roam --help
  git roam help version
  git roam version
  git roam check
  git roam status
  git roam enable
  git roam disable
  git roam node create --path /path/to/worktrees
  git roam checkpoint -m 'Confirm this knowledge version'
  git roam deploy --path /path/to/worktrees
  git roam undeploy
#+end_src

Help and version queries do not require a Git repository. Successful queries write to standard output and exit with status 0. Invalid commands, help topics, or arguments write a diagnostic to standard error and exit with status 2.

* Read-only repository inspection
=check= validates stored Node histories and the managed local branch dependency closure. =status= shows tip type, latest Checkpoint, unconfirmed Content, retained Checkpoint count, exact dependencies, and Git-recorded worktree paths. Dependencies displayed for a Content tip belong to its latest Checkpoint; Content itself has no formal dependency declaration. Main worktrees are distinguished from linked deployments, and detached worktrees are not Node deployments.

Both commands accept =--node <uuid>=. Otherwise they infer a Node from the current Node worktree, or use repository scope. Node scope also checks the persistent branches required by that Node's retained history. Ordinary branches, tags, and remote-tracking refs do not count as managed Node branches. These commands work before protection has been enabled.

#+begin_src sh
  git roam check --node 11111111-1111-4111-8111-111111111111
  git roam status --node 11111111-1111-4111-8111-111111111111
#+end_src

Inspection does not fetch or modify refs, index, worktrees or history. It reads stored parents without replace-object or graft interpretation and reports missing reachable objects or shallow history as incomplete evidence. It compares managed refs before and after inspection; a changed observation is reported separately from a confirmed protocol or closure violation. This comparison does not provide isolation from arbitrary concurrent Git writers.

Exit status is 0 for a successful check or status, 1 for a protocol or managed-state violation, 2 for invalid arguments, and 3 for unavailable evidence, Git read failure or a changing observation. Diagnostics distinguish a missing dependency branch from a branch that does not retain the required Checkpoint. No repair or protection installation is performed.

* Native Git and tests
The Nix package selects standard Git from its locked nixpkgs input. Direct Cabal builds use =git= from =PATH= unless =GIT_ROAM_GIT= selects another executable at compile time. The adapter retains ordinary Git configuration and passes arguments directly to the native process API.

The test suites cover CLI behavior, SHA-1 and SHA-256 object IDs, native Git failures, binary input/output, argument boundaries, and repository discovery for ordinary, bare, and linked worktrees. Git integration tests use dedicated temporary repositories and isolated configuration.

Cabal declares the CLI test dependency through =build-tool-depends=. The tests locate the resulting executable on =PATH=. The Nix package selects the GHC 9.12 package set, including its Cabal build driver. No test executable path is injected by Nix.

* Repository protection
=enable= configures this executable's named =reference-transaction= Hook in the common repository configuration. It can run before knowledge history or dependency closure is valid, creates no Node or worktree, and is idempotent when the installed configuration matches. Conflicting, inherited or incomplete configuration is refused rather than overwritten. Other Hooks remain configured and active.

Ordinary Git updates may edit or replace unconfirmed Content and add valid Checkpoints. They must retain the Root and every already retained formal Checkpoint. Ordinary Node branch creation, deletion and Checkpoint discard are refused. The Hook validates the complete candidate set of a multi-ref transaction in =prepared=; Content updates that keep the same formal history use a local history check rather than a full repository scan.

=disable= removes only Git-roam's matching protection configuration and requires that all Node linked worktrees have been safely removed first. This includes manually created linked worktrees. It does not delete branches or objects, or switch or remove the main worktree. Use =undeploy= to remove Node linked worktrees before disabling protection.

Protection operations share a common-directory operation lock. A busy or unavailable lock causes refusal and is not automatically removed. This coordination and Git's ref transactions do not guarantee isolation from arbitrary external writers. Internal controlled operations must validate their plan and use conditional ref updates; their per-call bypass disables only Git-roam's own named Hook. Destructive history operations remain later work.

The current build uses Git 2.56.0. Protection requires configured named Hook support and enforces a Git 2.54 version floor; the full behavior on that minimum version and on other platforms remains unverified. Hook configuration identifies the enabled executable, so a different executable or divergent configuration requires an explicit lifecycle/configuration review. Configuration writes use Git's own locking; a failed installation is not claimed to be an atomic configuration transaction.

* History protocol library
The Haskell library validates decoded commit and tree objects through an injectable object source. It checks canonical UUID directories and regular-file =.roam= markers, unique Roots, single-parent Content chains, and Checkpoint parent roles and tree equality. Required missing objects and incomplete history are reported as unavailable evidence.

A Checkpoint has parents =[q, w, ...]=. Its first parent =q= is the same Node's Root or a Checkpoint. Its second parent =w= ends a Content chain based on =q=, and supplies the exact Checkpoint tree. Additional same-UUID Checkpoints retain other formal history branches; different-UUID Checkpoints declare the complete direct external dependencies, with one version per external UUID.

The library projects Checkpoints to their content tree, formal predecessors =H= and complete dependencies =D=. Root and Content do not project to formal knowledge versions. Empty dependencies differ from Content having no formal dependency declaration. Formal-history traversal follows all same-Node formal predecessors; combined knowledge ancestry also follows external dependencies. Ordinary Git ancestry cannot substitute for the former.

Protocol tests include malformed graphs, same-Node history convergence, empty-diff Content, dependency replacement and removal, and generated SHA-1/SHA-256 graphs comparing projected knowledge ancestry with raw Git ancestry. The native object reader and shared managed-state validator power =check= and =status=. A pure transition validator checks Root consistency and preservation of all existing formal Checkpoints and is shared with realtime reference protection.

* Internal worktree foundation
The library provides whole-set worktree planning and protected native add/remove primitives used by Node creation, deployment and undeployment. Planning preserves existing manual or moved Node linked worktrees, distinguishes main and detached worktrees, and refuses locked, missing or prunable targets. Main worktrees are never removal targets.

Default directory names hash the canonical UUID's ASCII bytes with SHA-256, encode the first five digest bytes using standard Base32, and use eight lowercase characters without padding. Names are derived paths, with explicit collision checks; no mapping or deployment-root registry is stored.

Deployment roots must be empty or contain only existing Node linked worktrees. Nested roots must be wholly ignored by their outer Git repository and contain no tracked outer paths. Symlink path components, occupied targets and Git administration directories are refused. Existing deployments are not relocated when a different root is supplied.

Removal planning checks all targets before execution, including staged, unstaged, untracked and ignored data, empty untracked directories, special files, unfinished Git operations and nested worktrees. Assume-unchanged or skip-worktree index entries and submodules are conservatively refused. Only selected nested Node linked worktrees may be removed, deepest first. Execution rechecks the plan under the repository operation lock and never uses force, stash or clean. These primitives do not modify Node branches or claim filesystem atomicity; a failed Git operation can leave residual state for its caller to report and handle conservatively.

* Full deployment after clone or fetch
Enable protection, fetch the desired history with ordinary Git, then deploy:

#+begin_src sh
  git roam enable
  git fetch origin
  git roam deploy --path /path/to/worktrees
  git roam check
#+end_src

=deploy= targets every local UUID Node branch and every selected canonical fetched Node candidate missing a local branch. It does not select Node subsets, fetch objects, advance existing local branches, merge histories or move existing worktrees. Existing local tips always take precedence over remote candidates. A Node checked out in the main worktree is reported as a conflict; deployment does not switch that worktree.

Candidate discovery uses =refs/remotes/<remote>/<uuid>=. One source is usable; sources with the same OID coalesce deterministically. Different OIDs are refused even when =checkout.defaultRemote= would choose one. Use =--remote origin= to restrict missing-Node discovery to that remote; all existing local Nodes remain included. Candidates must have matching UUID identities and complete legal histories. Dependencies must be retained by branches in the complete final set; deployment never guesses a missing source's latest tip from an old dependency Checkpoint.

The complete candidate set and paths are checked before structural writes. Missing local branches are established together using a conditional Git ref transaction, then Git's native =branch --set-upstream-to= configures tracking and =worktree add= performs checkout. Existing local branch configuration for a missing Node causes refusal. This supports fetched histories whose dependencies cannot be established one branch at a time. New worktrees use =<path>/<short(uuid)>=; already deployed Nodes keep their actual paths. Relative =--path= is resolved from the invocation directory. A relative root inside an existing worktree must already be wholly ignored; Git-roam does not edit ignore rules.

On failure, the command reports failure and actual residual state. Compensation only attempts worktrees newly created by this operation, with unchanged planned tips and safe contents. New branches can be removed only if unchanged, unchecked-out, and unnecessary to the dependency closure of retained histories. Changed or required branches stay together. Preexisting branches and worktrees are retained. A failed compensation stops conservatively, and the deployment root may remain empty. Neither multi-worktree filesystem atomicity nor isolation from arbitrary external writers is promised. Concurrent changes or incomplete observations require inspection, not automatic repair.

Tests exercise actual local clone/fetch, tracking setup, both object formats and reference backends, equivalent and divergent sources, incomplete-to-complete dependency closure, stale conditional updates, and checkout-Hook failures with and without new user data.

* Create and edit a Node
#+begin_src sh
  git roam enable
  git roam node create --path /path/to/worktrees
#+end_src

=node create= generates a canonical UUIDv4 and creates a Root, its persistent local UUID branch, and an immediately editable linked worktree. Output contains =node <uuid>=, =root <oid>= and the actual =worktree= path. The path uses the same eight-character short name as deployment. Only this new Node receives a worktree; existing undeployed Nodes are left for a later full =deploy=. Unrelated main or locked Node worktrees are left alone and do not prevent creation when the new target is safe.

The Root has no parents and contains only =<uuid>/.roam=, an empty regular file. Knowledge content belongs inside that UUID directory. Use ordinary Git to stage and commit edits there, retaining the marker:

#+begin_src sh
  cd <reported-worktree>/<uuid>
  # Create or edit note.org here.
  git add note.org
  git commit -m 'Write a note'
  git roam status
#+end_src

These single-parent commits are unconfirmed Content; they are not Checkpoints and do not declare formal dependencies. Ordinary Git can revise this Content under the enabled history protection rules. Use =checkpoint= to confirm the committed state as a formal knowledge version.

Creation requires matching enabled protection and valid managed history. It uses Git's configured author/committer identities and constructs objects without using or changing the current index. Before object writes, it checks UUID/ref/configuration conflicts, paths and native author/committer availability. The new Root and complete target branch state are validated before conditional reference creation. Existing local UUIDs, canonical fetched identities, an ambiguous UUID tag, an existing unborn checkout of that UUID, occupied paths and stale branch configuration cause refusal.

A failed checkout attempts compensation only for its proven new unchanged branch and safely removable worktree. User files, changed Content history, changed branch configuration and competing creation results are retained and reported. Creation does not fetch, establish tracking for a new identity, reset user changes or manually delete Git objects; failed attempts can leave unreachable objects and an empty deployment parent directory.

* Create a Checkpoint with complete dependencies
Run inside a Node worktree or select its canonical UUID explicitly:

#+begin_src sh
  git roam checkpoint -m 'Confirm this knowledge version'
  git roam checkpoint --node <uuid> -F message.txt --depend <external-checkpoint>
  git roam checkpoint --depend <new-external-checkpoint> -m 'Replace a dependency version'
  git roam checkpoint --drop-dependency <external-uuid> -m 'Remove a direct dependency'
  git roam checkpoint --clear-dependencies -m 'Declare no direct dependencies'
#+end_src

The first Checkpoint requires an existing Content commit. Commit edits with ordinary Git first, or use =git commit --allow-empty= for an intentional empty Content commit. A Content tip supplies its committed tree and entire editing chain. When the tip is already a Checkpoint, the command creates a new same-tree Content object based on it, then creates the next Checkpoint. Only the final branch ref is advanced, once. No Content is automatically squashed, and the previous Checkpoint's second parent is never reused.

Each Checkpoint directly records its complete final dependency set. Construction starts from the main predecessor's complete direct mapping, or empty before the first Checkpoint. Repeat =--depend <revision>= to add different external Nodes; an already declared external UUID is replaced by its newly selected version. Repeated =--drop-dependency <uuid>= removes inherited entries. =--clear-dependencies= may combine with additions to replace the whole set. Clearing together with removals, removing an absent entry, duplicate versions for one UUID, and removing/replacing the same UUID together are refused.

Dependency inputs accept Git refs and unambiguous commit OIDs, including unique hexadecimal abbreviations. Git resolves names; full Git revision expressions such as =~=, =^=, =@{...}=, ranges and paths are not supported. Lightweight and annotated tags may name retained Checkpoints. Inputs resolve once to exact commit OIDs and must be Checkpoints retained in the corresponding local Node branches' formal histories. Root, Content, self dependencies, ambiguous names and unretained fetched objects are refused. A dependency branch with a Content tip is not silently interpreted as its latest Checkpoint; select a ref or OID naming the actual Checkpoint. The command does not construct formal-history merges, but preserves already merged formal histories through its main predecessor.

Knowledge history and object completeness are checked using stored commit/tree objects and blob metadata. Grafts and replacement refs do not redefine these relationships. Shallow repositories and missing required objects remain unsupported. No temporary repository view or deprecated graft override is used.

Messages use exactly one =-m= or =-F=. =-F -= reads standard input. Nonempty UTF-8 text without NUL bytes is required; no Conventional Commit title or editor is required. Commit construction uses UTF-8 without changing repository encoding configuration. Output identifies the Node, new Checkpoint, selected Content and complete dependency mapping.

The tree always equals the previous branch tip's committed tree. Staged, unstaged, untracked and ignored data are excluded and retained, including in a main worktree. The command never runs =write-tree= or creates a commit from the working index. Shared protocol, normal-state and formal-retention checks validate the final candidate before a ref transaction with expected-old and dependency-ref verification. Other reference Hooks remain active. Missing author/committer configuration or conflicting edits prevent installation.

Failed attempts may leave unreachable objects. Once a ref update succeeds, follow-up failure is reported without rolling back formal history. Failure diagnostics include any constructed candidate OID and distinguish confirmed installation from an uncertain update result. The command does not claim isolation from arbitrary external writers; inspect actual refs and run =check= after an uncertain outcome.

* Full undeployment
#+begin_src sh
  git roam undeploy
  git roam check
  git roam disable
#+end_src

=undeploy= discovers every registered linked worktree attached to a canonical Node branch, including manual and moved worktrees. It needs no path and accepts no subset or force option. Enabled matching protection and valid complete managed history are required. Every removal target is preflighted before the first removal; any known unsafe target prevents the whole operation from starting. An invalid or incomplete knowledge history is reported for review rather than repaired by undeployment.

Clean nested Node linked worktrees are removed deepest first. Uncommitted, untracked, ignored and otherwise unprotected data, locked or prunable registrations, unfinished Git operations, and non-target nested worktrees prevent removal. Main worktrees are retained and reported separately, even when attached to a Node branch. Detached and ordinary non-Node worktrees are left in place. Main or other non-target user files are not cleaned.

Node branches, commit objects, tracking configuration and Git-roam protection remain in place. Repeating =undeploy= with no linked targets succeeds. The command can run inside a target worktree; later Git operations use the common Git directory after the invocation directory is removed. A deployment parent directory may remain empty.

Removal is not a filesystem transaction. If Git fails or state changes after execution starts, the operation stops, reports failure with confirmed removals and available actual remaining state, and leaves newly edited or unsafe worktrees in place. It does not automatically recreate removed worktrees, reset files or move refs. Successful removal is followed by shared history validation, ref preservation, remaining-worktree and protection checks. These checks detect anomalies without claiming isolation from arbitrary external processes.
