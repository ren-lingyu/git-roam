# v0.2.0 isolated performance experiment

The user requested both reader and shared-ancestry performance experiments,
plus archival assessment, and explicitly excluded repeating the old patched-Git
and batch-worktree experiments. Workspace: tmp/v020-performance/. Project main,
staged documents, source, lock and protection remain unchanged.

prepare.py restores 51 files from committed d8503af. Native source is exact;
legacy-source changes only Delete.collect's remaining-tip query back to mapM
single-start reachableHistory followed by Set.unions. This is a narrow algorithm
control against the current protocol, not a previous released binary. SOURCE.json
records base blobs/hashes and the exact control expression. Reader one-shot
control is a bare Git adapter delegating each call to nativeGit; production mode
preserves its session capability through observeGit. No old q,w graph is used.

Fixtures are deterministic packed SHA-1/files repos. All Roots are created first.
Each ordinary Node gets Content then a same-tree Checkpoint with an external
Root context. Shared cases give the first Node 256 same-tree Content ancestors
and point other Nodes' Checkpoints at that anchor Checkpoint. The anchor itself
references another Root, preserving an acyclic valid Git DAG. The last Node is
the deletion target, with exactly three exclusive commits. New import-stream
hashes identify these v0.2.0 datasets, not the incompatible old experiment data.

The harness compares full inspectState; pure reachability after loading the same
validated graph; and actual previewDelete in native versus reverted-control
libraries. Every pair checks semantic digests; full deletion reports/plan IDs
must also match within the same fixture. All refs are hashed before/after each
read-only measurement. Pure-query timing excludes graph loading but includes
query/exclusive-set/digest forcing; its maximum process RSS includes loading.
Full inspect/preview timing includes digest forcing. This does not time native
ref deletion or GC. Instrumented Git counts exclude driver setup/ref audits.

Toolchain uses the original archived nixpkgs lock, Git and GHC 9.12 package set.
Benchmark copies skip the already independently passed 250-case matrix; no
production test configuration changes or new correctness-pass claim follows.
An initial flake evaluation failed because outer callPackage overrode the wrong
function argument set for dontCheck. Direct import of the project package
expression resolved that setup issue; the corrected no-build flake check passed.
Both benchmark libraries/tools built successfully. The corrected no-build
flake evaluation passed. The complete production source was not retested here;
these experiment package copies intentionally disable doCheck only.

All modes/repeats are serial, Nix job/core one, GHC -N1 -M1G and one pack thread.
The user explicitly authorized on-demand 300s build, 900s inspect-scale and
300s shared-scale commands for this experiment; pilot stages use 120s outer
bounds. Inner measurement bounds are 60s pilot, 180s inspect-scale, 120s shared
scale. Failures/timeouts stop without automatic retry or resource expansion.
A managed heap cap is not a physical RSS cap. No OS cache flushing, cold-storage,
all-platform, minimum-Git or arbitrary-process concurrency guarantee is claimed.

Archival assessment selected the new bounded reproducibility/audit evidence.
The byte-verified snapshot is [MANIFEST](../archive/2026-11-10T12-21-51Z--d8503af-v020-performance/MANIFEST.md).
It contains 13 recipe/report/compact-result files, 77,891 source bytes, no
recovered source trees, packs, binaries or full logs. Selection, provenance,
reconstruction and limits are documented there; old archives remain unchanged.

## Pilot observations

Both pilots completed all paired repeats with matching semantic digests and
unchanged ref hashes. Complete deletion reports/plan IDs also matched per case.
Git 2.56.0, GHC 9.12.3, x86_64-linux; the same script/harness/source manifests
apply to the following scale stages.

| 1,000 Nodes | Median seconds, control / native | Median max RSS KiB | Git launches |
| --- | --- | --- | --- |
| Complete inspection | 9.515691 / 0.198297 | 53,980 / 39,256 | 6,011 / 11 |
| Loaded shared-history query | 0.098355 / 0.007795 | 37,144 / 27,488 | 11 / 11 total, zero during query |
| Complete deletion preview | 0.554772 / 0.466648 | 76,732 / 53,860 | 39 / 39 |

Shared depth is 256 Content commits on the anchor Node. Pure query improvement
must not be described as the end-to-end preview speedup; full validation and
Git I/O remain in the latter. No new performance threshold is imposed on CI.

## Final scale observations

All four stages completed: 36 successful measurements, three repeats per mode.
Semantic/full fingerprints match per comparison group; all ref hashes remain
unchanged. Both source copies were rechecked against the source manifest.

| 10,000 Nodes | Median seconds, control / native | Median max RSS KiB | Git launches |
| --- | --- | --- | --- |
| Complete inspection | 89.570110 / 1.706268 | 472,368 / 422,904 | 60,011 / 11 |
| Loaded shared-history query | 0.936478 / 0.060132 | 246,524 / 204,588 | 11 / 11 total, zero during query |
| Complete deletion preview | 8.174572 / 4.802624 | 665,460 / 496,480 | 39 / 39 |

Persistent inspection is about 52.49x faster at 10,000 Nodes, with one raw batch
reader rather than 60,001. Shared traversal is about 15.57x faster in isolation,
but actual full preview improves about 1.70x; it still performs validation/Git
I/O and three persistent reading sessions. All preview exclusive sets contain
three commits. No OOM or measurement timeout; greatest observed GNU time max
RSS is 666,124 KiB, not an aggregate tree or enforced physical memory ceiling.
Results support the current reader and multi-start algorithm on these fixtures;
no further product change or full suite rerun is justified by this experiment.
