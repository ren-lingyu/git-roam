* DONE v0.2.0
CLOSED: [2026-11-10 Tue 15:29]
:PROPERTIES:
:CUSTOM_ID: v0.2.0
:END:
This version introduces the incompatible Checkpoint context protocol in the
CLI and repository Hook. See
[[file:CHANGELOGS/v0.2.0.org][Detailed release notes]].

** Removed
- *Breaking:* Retire =git roam discard= and its formal successor/dependency-closure workflow. Use ordinary Git to revise valid same-Root history; delete Node branches explicitly with =node delete= when appropriate.

** Changed
- *Breaking:* Replace the v0.1.0 formal Checkpoint dependency mapping and special Content/Checkpoint encoding with an immediate same-Node first parent plus caller-selected external context parents. No automatic migration from v0.1.0 histories is provided.
- *Breaking:* Replace =checkpoint --depend=, =--drop-dependency=, and =--clear-dependencies= with one or more explicit =--context <revision>= arguments. At least one context is required; no context is inherited and no synthetic Content commit is created.
- Validate context commits by their recorded ancestry and objects without requiring retention by the referenced Node's current branch. Ordinary Git history rewrites may drop old Checkpoints if Root identity and structural validity are preserved.
- Update =check=, =status= and the repository Hook for context ancestry rather than managed dependency closure. =status= reports the latest first-parent Checkpoint's direct contexts.
- Make =node delete= non-cascading when other Node histories reference the deleted Node's commits; preview reports loss of reachability from remaining managed refs, not physical object deletion.

** Fixed
- Reject invalid or duplicate entry names in nested Node content directories when checking history or validating reference updates.

** Added
- Allow =--context= to select another Node's Root, ordinary Content, or Checkpoint, including older commits no longer retained by its current local branch.
- Allow multiple distinct context commits from one external Node with a compatibility warning; reject repeated context OIDs and same-Node contexts.

See [[file:CHANGELOGS/v0.1.0.org][Detailed release notes]].

** Changed
- Allow unrelated content in deployment roots while refusing occupied or indexed Node worktree targets and unsafe tracked ancestors.
- Resolve the configured Git-roam reference-transaction Hook through =PATH= and migrate recognized legacy commands.
- Reuse a scoped raw Git object reader within each history validation operation.

** Added
- Create UUID-identified Nodes with independent Git histories and linked worktrees; support explicit identities and text, JSON, or CBOR creation output.
- Record Content with ordinary Git and create formal Checkpoints with complete, exact-version external dependencies.
- Inspect and protect Node history, retained Checkpoints, and managed dependency closure.
- Deploy and undeploy complete Node worktree sets with conservative filesystem and history safety checks.
- Preview and confirm explicit Checkpoint discard or deletion of an unreferenced Node.
